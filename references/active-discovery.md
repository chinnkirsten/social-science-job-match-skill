# 主动岗位发现

这个流程用于“给一份简历，主动找出适合的岗位”。搜索结果只用于发现，不能直接进入可投清单。

## 1. 先固定三个条件

`intake.json` 必须包含一个招聘模式、明确城市和1—5个已确认职能方向：

```json
{
  "employment_mode": "campus_full_time",
  "locations": ["杭州", "广州", "深圳"],
  "target_directions": ["财务分析", "管理会计", "审计"],
  "recruitment_season": "autumn"
}
```

方向应当是招聘中会出现的职能语言，不是“好公司”、“发展好”或一长串个性形容词。如果用户未指定，先从已确认经历中提出最多5个候选方向，说明每个方向由哪些经历支撑，再请用户选择。用户明确授权代选时，记录这项授权及方向依据，不重复询问偏好；它不授权模型确认经历事实。

## 2. 生成可复查的检索计划

```bash
python scripts/prepare_job_match.py plan --intake ../jobmatch-private/intake.json --output ../jobmatch-private/search-plan.json
```

计划对“方向 × 城市”生成有编号的检索式。使用当前会话可用的搜索工具逐条执行；单次工具有查询数限制时分批执行。优先收集雇主官网、官方 ATS、政府、高校和国际组织招聘页；聚合页仅用于找到具体职位链接。

按以下顺序减少无效检索，不设置会削减覆盖面的固定总查询上限：

- 先精读少量具体JD，检查岗位模式、地区、学历/届别、必要技能与时间要求，再根据排除原因扩展词汇。不要先生成数百条线索再判断方向是否合适。
- 优先复用已有查询记录、规范URL和雇主岗位ID；同轮相同查询、同一页面不因工具或Agent不同重复执行。重复网址先归并，不先生成多份改写再去重；保留不同来源的冲突信息。
- 每批记录新增线索、读全JD、通过数量和主要排除原因。无新增时换授权范围内的来源或职能词，不把同义查询无限重跑；方向不是配额，不为凑数放宽相关性。
- 先完成资格筛选，再对通过或确需解释的待确认项写详细建议；不要为明显关闭、模式错误或硬性条件不满足的岗位生成完整改写。
- 不在搜索词中提交个人简历全文或身份信息；不凭搜索摘要宣布可投。无搜索工具就说明只能处理提供的入口。

当前项目可选线索源为 `98_技术与代码/shuimian_final/public/assets/data/ra-jobs.json` 与 `98_技术与代码/shuimian_final/public/qiuzhi.html` 及其数据源。路径不存在时直接查公开来源，不建立虚假文件，不让公开Skill依赖本地目录。

检索词同时覆盖专业与职能，例如研究、政策、评估、用户研究、公共事务、内容编辑、教育、出版、公益项目，再加城市、级别和招聘模式。财务、工程、纯行政等方向只有在用户真实经历与本轮范围支持时才纳入，不因“社科”标签一概接受或排除。校招检索可用批次、应届或届别词，但按实际用工形式判断；“有实习经历优先”不意味着该岗是实习。

保存结果时一项一行，不要将简历文本写入搜索结果：

```json
[
  {"query_id":"q-001","url":"https://careers.example.org/jobs/123","title":"结果标题","snippet":"搜索摘要"}
]
```

示例域名不是真实岗位。不得伪造未执行的搜索结果。

## 3. 导入待复核候选池

```bash
python scripts/prepare_job_match.py search-results --results ../jobmatch-private/search-results.json --intake ../jobmatch-private/intake.json --output ../jobmatch-private/source-draft.json
```

导入会按规范URL去重，并保留来自哪个方向和城市查询。它不请求职位页，也不判断在招。

逐条打开候选页后，`source-review.json` 除了原有的具体JD、范围与来源核对，还要确认方向：

```json
{
  "draft_sha256":"使用当前草稿摘要",
  "human_confirmed":true,
  "sources":[
    {"id":"候选链接ID","specific_jd_confirmed":true,"scope_confirmed":true,
     "direction_confirmed":true,"source_tier":"employer_official"}
  ]
}
```

导出时会将已复核职位所在主机名加入本次允许范围。抓取条款和人工复核仍然保留，不因搜索结果可访问而自动放行。

逐条保存机构、职位原名、地点/远程规定、雇佣形式、发布日期、截止日、职责、全部必需条件、申请材料、工作许可与申请路径。原JD、适用的官方薪级表或政府标准未披露待遇时，不编造数字；分清税前/税后、基本工资/总包、月薪/年薪、合同期与货币。学生资助包不当作全职工资，汇率或生活成本估算须另有当日可靠来源和方法。

平台直发详情须连同企业档案核对主体、地址和岗位归属，不能凭Logo判断官方。保留发布日期、入职日、滚动审查日与截止日的区别；刷新时间陈旧但截止日延长时注明疑点。状态与条件冲突按 `qualification.md` 处理；无法取得完整JD时留在待核验池。研究岗位的田野、驻地、语言、持证与安全要求写在资格或风险旁。

人才库、意向征集（roster、EOI、Call for CVs）和没有具体空缺的广告不进入可投清单。ATS询问是否需要签证担保不构成担保承诺，不推断工作许可、远程资格或雇主声誉。集团旗下学校和基金会按真实机构标注，会计师事务所等明确其合伙企业形式，不借集团名凑公司数。

## 4. 覆盖与停止条件

记录每个方向的查询数、线索数、具体JD数、在招数和资格通过数。达到20家不同雇主且逐条完成复核后停止。若确认的方向与地区范围已执行完整检索仍不足20家，交付阶段报告，列出差额和排除原因；不自动改城市、招聘模式或方向来凑数。

“全网”表示跨多个公开来源执行计划内检索，不表示穷尽互联网所有页面。搜索工具、登录和站点条款限制必须在报告中说明。
