# 报告依据、岗位资料与开源能力

## 依据不是一个匹配分数

报告的必要依据是候选人事实与具体在招JD；可比较的岗位资料帮助说明本批岗位的共同要求，职业技能标准按需辅助归一化。未实际使用分类库时明确写未使用，不能把注册表中的项目自动列为报告依据。

1. **经历记录**：只收录简历、作品和用户补充中能够定位的事实。每项给经历编号、原文位置、完成状态和可证明技能。推断与待确认项另列。
2. **具体岗位资料**：来自雇主官网、官方 ATS 或可核验的雇主直发详情。每岗保留完整链接、核验时间、在招依据、职责、全部必需条件和申请路径。
3. **同批岗位资料**：由同一招聘模式、地区和检索时间窗内的可比 JD 组成。它只回答“本批样本中反复出现什么”，不能覆盖某一具体 JD 的原文。
4. **职业技能标准**：用 O*NET 或 ESCO 统一近义职业与技能，帮助发现漏词和迁移路径。它们是欧美职业分类，不是中国校招资格规则，也不能证明岗位正在招聘。

报告里的每条资格结论必须能回到前两类材料；趋势、技能频率和简历基础版本结构可参考后两类资料。不存在来源的模型判断只能作为待审建议。

## 来源等级

| 等级 | `source_tier` | 可以做什么 | 不能做什么 |
|---|---|---|---|
| T1 | `employer_official` | 支持岗位事实、开放状态和资格判断 | 页面仍需在交付前复核 |
| T1 | `official_ats` | 支持具体 JD、申请路径和开放状态 | 不能仅凭 HTTP 200 判定开放 |
| T2 | `employer_verified_platform` | 雇主身份和完整详情均可核验时支持岗位判断 | 搜索摘要或未认证账号不足 |
| T3 | `official_repost` | 发现线索、交叉核对日期和活动批次 | 不单独进入“已确认可投”主清单 |
| T4 | `aggregator` | 扩大候选池和发现检索词 | 不支持开放状态、薪酬、资格或主清单结论 |

搜索引擎摘要、Agent 转述、网页缓存和聚合站标签都不改变来源等级。主清单岗位只能使用 T1 或满足全部 T2 条件的来源。

## 同批岗位资料的建库规则

- 先锁定 `employment_mode`、地区、毕业届别或工作年限和检索时间窗；实习、应届校招和社招分别建岗位资料，不能混合计算词频。
- 每条岗位资料至少保存 `corpus_id`、公司归并键、职位原名、招聘模式、地区、来源等级、URL、采集时间、开放状态、职责摘录、必需项摘录和排除原因。保留原始页面快照、合法缓存或内容校验码；快照不可得时明确记录。
- 单批岗位一律写“本批样本观察”。样本量、雇主数和来源比例只作描述性统计，不能触发“市场趋势”结论。趋势分析需另有跨时段可比样本、抽样方法和审阅；本脚本不生成此结论。
- 报告必须列出候选池规模、完整 JD 数、不同雇主数、各来源等级数量、排除数量和截至时间。不能把公司名称列表当作岗位资料量。
- 统计必需项与加分项时分开计数；同一 JD 中重复出现的词只计一次。先保留中文原词，再映射标准技能，不用机器翻译悄悄替换原意。
- 岗位资料频率用于选择简历基础版本、关键词和准备顺序；具体岗位是否满足仍按该 JD 与已有经历材料逐项判断。
- 个人简历、联系方式、私人作品和投递状态不进入共享岗位资料或开源仓库。第三方数据按许可证和网站条款使用，不绕过登录、付费墙或反爬措施。

## 可结合的开源项目

所有已评估组件、固定版本、许可证、用途和可信边界统一记录在 `integrations/open_source_stack.json`，执行约定见 `integrations/README.md`。本节解释选择原则；注册表是机器可检查的组件清单。

### 现在纳入方法层

- [O*NET Database](https://www.onetcenter.org/database.html)：职业、任务、技能、工作活动和工作情境的开放标准数据，可下载 CSV、JSON、SQL 或通过 API 使用。用于职业基准和技能同义归并，不替代中国岗位原文。
- [ESCO](https://esco.ec.europa.eu/en/use-esco)：欧盟的职业与技能分类，提供下载、API、稳定 URI 和多语言标签。用于建立“岗位—技能—近邻职业”关系；版本号必须写入报告。
- [Docling](https://github.com/docling-project/docling)：本地解析 PDF、DOCX、网页、表格和版面，可将简历与 PDF JD 转成结构化 JSON/Markdown。适合隐私优先的预处理；解析结果仍需对照原页。
- [Crawl4AI](https://github.com/unclecode/crawl4ai)：把公开网页抽取成 Markdown 或结构化记录，可作为官方页面批量采集的可选执行器。只抓允许访问的公开页面，固定并审查版本，不绕过站点限制。

### 可选实验与评估

- [tabiya-open-dataset](https://github.com/tabiya-tech/tabiya-open-dataset)：把 ESCO 转成易用 CSV，可用于离线原型；其 ESCO 版本可能落后于官方当前版，使用时同时记录上游版本。
- [tabiya-livelihoods-classifier](https://github.com/tabiya-tech/tabiya-livelihoods-classifier)：提供职业描述到 ESCO 的分类模型、数据与评估，可借鉴分类和测评方法；模型输出必须人工复核。
- [esco-skill-extractor](https://github.com/Datalab-AUTH/esco-skill-extractor)：先匹配职业、再抽取并链接 ESCO 技能的两阶段流程，可用本地模型运行；适合候选技能归一化，不用于判定资格。
- [Compass](https://github.com/tabiya-tech/compass)：通过对话从正式和非正式经历中发现技能，适合借鉴“补充经历说明”流程；新发现的技能必须由用户确认并关联原始经历。
- [Resume Matcher](https://github.com/srbhr/Resume-Matcher)：可借鉴 JD 关键词、相似段落和差距可视化；未经校准的相似度不能写成录用概率或资格结论。

### 不作为报告依据

- 自动投递、代登录、收集邮箱或依赖规避封禁的 Agent 不接入。本技能没有代投授权，也不能把平台规避策略当作数据能力。
- [JobSpy](https://github.com/speedyapply/JobSpy)只能作为特定境外平台的可选发现工具；项目自身提示部分站点会强烈限流，且对中国校招官网覆盖有限。其结果必须回到官方 JD，不能直接进入主清单。
- LangGraph 等通用 Agent 框架只负责状态编排，不提供职业事实或招聘数据。流程尚未需要长时运行和人工审批节点时，不新增这类依赖。

## Agent 分工与复核职责

需要自动化时最多拆成三个角色，三者读写同一份结构化记录，不各自生成互相冲突的结论：

1. **Source Scout**：发现和抽取公开 JD，记录来源等级与失败原因，不判断候选人合格。
2. **Evidence Mapper**：把 JD 条件与已有经历材料、标准技能逐项对应，未知项保持未知，不补写经历。
3. **Auditor**：复核来源、开放状态、必需条件、去重和报告措辞；只有复核通过的记录可设 `selected=true`。

Agent 声称“已核验”，不能替代招聘页面和经历材料。复核人员必须能打开原始来源，完整性检查必须运行，最终报告还要人工检查。若多个 Agent 同时工作，岗位记录使用稳定 ID，并保留采集、映射和复核时间，避免后写结果覆盖来源原文。

## 报告中必须披露

在首页或“依据与限制”一节列出：方法版本、经历记录数量、候选池数量、完整 JD 数、不同雇主数、来源等级分布、岗位资料截至时间、采用的分类库与版本、不能核验的来源、主要样本偏差。使用开源解析或分类工具时，写清它只承担解析、归一化或候选发现中的哪一步，不把项目名当作权威背书。
